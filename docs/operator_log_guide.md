# 운영 로그 가이드

이 문서는 `strategy_live.out`에서 사람이 바로 봐야 하는 로그만 설명한다.
상세 원인 분석은 `strategy_live.jsonl`, final report, DB 리포트를 기준으로 본다.

## 남기는 로그

- `[런타임]`: 전략 프로세스 시작/종료.
- `[시작]`: 실행 설정, 마진모드 확인, 거래소 준비 상태.
- `[진입]`: 신규 페어 진입 시도, 차단, 부분 체결, 체결 후 품질 확인.
- `[헷지]`: 첫 체결 이후 반대 거래소 헷지 진행 상태.
- `[페어]`: 페어 오픈, 청산 트리거, 종료 완료.
- `[페어종료]`: 페어 종료 주문 제출.
- `[위험]`: 초과 체결, 방향 불일치, 청산 실패, 복구 실패처럼 즉시 확인해야 하는 상황.
- `[종료]`: shutdown 정리 시작/완료.
- `[거래소]`, `[시세연결]`, `[계정갱신]`: 거래소 일시 장애나 연결 재시도처럼 운영 판단에 필요한 경고.

## 숨기는 로그

- 정상 account refresh 요청/성공/쿨다운 반복.
- 반복 websocket reconnect 원문.
- 반복 OKX retry 원문.
- 후보 스캔 전체 상세.

이 정보는 stdout에서만 숨긴다. 구조화 이벤트와 리포트에는 남겨서 사후 분석이 가능하다.

## 판단 기준

- `[위험]`이 나오면 즉시 JSONL/final report로 원인을 확인한다.
- `[페어][오픈]` 뒤에는 `[헷지][완료]`와 `[페어][종료완료]` 흐름을 확인한다.
- `[거래소][일시중단]`이 반복되면 신규 진입이 줄어들 수 있으나, 청산/복구 로그가 없는지 같이 본다.
- `[종료][정리완료] 잔여포지션=없음` 또는 final report의 `remaining_positions=[]`가 shutdown 통과 기준이다.
